[SLIDE 2 — ARCHITECTURE]  ~60 seconds
--------------------------------------------------------------------------------

[Show architecture_diagram.png]

"TaskTamer is built on four layers using Google's ADK:

1. At the top — an ADK Workflow graph with three nodes:
   - A Security Checkpoint that every message passes through first
   - An Orchestrator Node that coordinates the agents
   - A Final Response node that delivers output

2. The Orchestrator delegates to two specialist sub-agents:
   - Task Prioritizer Agent — handles to-do lists
   - Focus Scheduler Agent — handles calendar blocking

3. Both agents connect to a local MCP Server via stdio — exposing 4 tools:
   get_tasks, add_task, schedule_focus_block, get_calendar_events

4. And critically — a Human-in-the-Loop gate fires before any calendar
   mutation, requiring explicit user approval."

--------------------------------------------------------------------------------

[Open browser at http://127.0.0.1:18081]
[Select the 'app' agent from the dropdown]

"Let me start with a simple task. I'll type:"

>>> INPUT: "Add a high-priority task: Complete ADK presentation, due tomorrow."

[Wait for response]

"The security_checkpoint runs first — no PII detected, no injection keywords.
The scrubbed input flows to orchestrator_node, which routes to the orchestrator

Agent, which calls the add_task MCP tool.

The task is persisted to task_tamer_data.json and confirmed back to the user."

[SLIDE 4 — LIVE DEMO: HITL CALENDAR APPROVAL]  ~90 seconds
--------------------------------------------------------------------------------

"Now let me show you what makes TaskTamer unique — the Human-in-the-Loop gate.
I'll request a focus block:"

>>> INPUT: "Schedule a 60-minute focus block called 'Deep Work: ADK Coding'
            starting at 10am tomorrow."

[Wait for HITL interrupt prompt to appear]

"See that? The workflow paused. orchestrator_node detected 'schedule' in the
query and yielded a RequestInput interrupt before touching any calendar.

The user sees: '⚠️ Do you approve scheduling this focus block/event in your
calendar? Reply yes or no.'

This is ADK's Human-in-the-Loop primitive in action. Let me approve it."

>>> INPUT: "yes"

[Wait for final response]

"The workflow resumes. ctx.resume_inputs retrieves the approval, the
orchestrator delegates to Focus Scheduler Agent, which calls schedule_focus_block
via MCP. The event is saved and confirmed."

[SLIDE 7 — CODE HIGHLIGHTS]  ~60 seconds

[Show app/agent.py briefly]

"Under the hood, the ADK concepts are clean and composable:

- The workflow uses Workflow, Edge, START and @node decorators
- Conditional routing via ctx.route = 'pass' or 'SECURITY_EVENT'
- The HITL interrupt is a single yield: return RequestInput(interrupt_id=..., message=...)
- On resume: ctx.resume_inputs.get('confirm_schedule_block')
- Dynamic agent invocation: await ctx.run_node(orchestrator_agent, query)
- The MCP server is a 50-line FastMCP script spawned via StdioConnectionParams

The entire agent architecture is under 200 lines of Python."

BACKUP Q&A ANSWERS:

Q: Why a local MCP server instead of a real calendar API?
A: To avoid OAuth setup complexity during the hackathon. The architecture is
   identical — swapping the MCP server for a Google Calendar MCP is a 1-line
   change in connection_params.

Q: What is rerun_on_resume=True?
A: ADK requires this flag on any workflow node that calls ctx.run_node() or
   yields RequestInput. When the workflow resumes after a HITL interrupt, ADK
   re-runs the parent node to retrieve the child node's response. Without this
   flag, a ValueError is raised at startup.

Q: Could this scale to multiple users?
A: Yes — the App layer supports per-session state. Adding user-scoped storage
   would require replacing task_tamer_data.json with a session-keyed database,
   but the agent graph itself requires no changes.
